### Root Cause Analysis

**The Problem:**
Tool 3 was refactored to use the vLLM `/v1/chat/completions` endpoint with JSON schema response format. This approach worked reliably in testing but failed on **46 out of 50 real documents** with:

```
vLLM error: 400 Client Error: Bad Request
Failed to parse JSON response: Unterminated string starting at: line 2 column 11
```

**Why It Happened:**
- The chat endpoint with JSON schema constraint was too strict
- Real documents with complex schemas caused vLLM to generate malformed JSON
- The structured output constraint didn't play well with vLLM's inference behavior on diverse data

**Test Documents Affected:**
- `cd798399-8449-7324...` - SPOC Created Incidents Daily
- `9dc1d2e8-7871-36c0...` - SPOC Daily Incidents  
- `c38a5377-c042-49fc...` - SPOC Daily Incidents
- `138f0aba-e19b-5d91...` - 5199-TS.csv
- `91402a87-d24e-9034...` - Nesting Audits for EOD Reports
- ...and 40 more

### The Fix

**Reverted Tool 3** to use the `/v1/completions` endpoint with the original code-cleaning approach:

1. ✅ Uses completions endpoint (more reliable than chat)
2. ✅ Removes markdown formatting (```python, ```)
3. ✅ Filters out explanation text
4. ✅ Validates Python syntax
5. ✅ Includes schema code cache for speed

**Code Change**: `tools/generate_parser_script/tool.py:_call_vllm()`

## Lessons Learned

### 1. Test on Real Data Early
The JSON schema approach worked perfectly in unit tests but failed catastrophically on real diverse data. This demonstrates the critical importance of end-to-end testing before deployment.

### 2. JSON Schema Has Limits
While JSON schema response format (a mosaic pattern) works for structured extraction (PII fields), it's too rigid for code generation where the output format is less predictable.

### 3. Completions vs Chat Endpoints
- **Completions**: More robust for code generation (LLM just generates text)
- **Chat**: Better for structured interactions but adds overhead with JSON schema

### 4. Analyzer Validates Tools
The comprehensive analyzer (Tools 1-4 test runner) successfully identified the issue that would have been missed in isolated unit tests.
